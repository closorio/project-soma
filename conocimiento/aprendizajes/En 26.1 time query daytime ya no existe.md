# En 26.1 time query daytime ya no existe

En 26.1 el tiempo pasa por «timelines» y cambian las órdenes de `/time`. Los bancos que leen la hora por RCON fallan en el mundo `local`, aunque en el de supervivencia (1.21.11) siguen bien.

## Evidencia
Respuestas del servidor 26.1.2:

| orden | 26.1.2 |
|---|---|
| `time query daytime` | `Can't find element 'minecraft:daytime' of type 'minecraft:timeline'` |
| `time query day` | `Timeline minecraft:day is at 620 tick(s)`: son los ticks del día, **no** el número de día como en 1.21.11 |
| `time query gametime` | `The game time is 620 tick(s)` (igual que antes) |
| `time set 12000`, `time set day`, `time set night` | siguen igual |
| `gamerule doDaylightCycle` | no existe: ahora es `advance_time` |

`help time` en 26.1: `/time set (<time>|<timemarker>)`, `/time add`, `/time pause`, `/time resume`, `/time rate`, `/time query (time|<timeline>|gametime)`, `/time of <clock> …`.

## Qué hacer con ello
- Antes de medir noches en `local` (F8.0b), adaptar los que leen la hora: `entrenamiento/experimentos_sv.py:210`, `servidor-supervivencia/probar_noche.py:160` y `entrenamiento/experimento_mente_sv.py:207-208` (este último usa además `time query day` como número de día).
- Lo más seguro es un `hora()` común en `servidor/rcon.py` que pruebe `time query daytime` y, si falla, `time query day`, y que saque el número de día de `gametime` / 24000.
- Las reglas de juego también cambian de nombre en 26.1 (`keep_inventory`, `spawn_phantoms`, `advance_time`…): se comprueban con `/gamerule NOMBRE` antes de fiarse.
